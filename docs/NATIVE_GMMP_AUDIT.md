# GMMP localization and native-function audit — 28 September 2026

**Code audited:** `feature/multi-playlist-add`, after the maintainer accepted the complete Playlist folders feature on the tested GMMP **4.2.0** device. This is a **source-level audit**, grounded in the repository implementation and the earlier documented investigation of the supplied original GMMP 4.2.0 APK. It is **not** a claim that all 76 raw APK language codes, every skin, or every action listed below were newly exercised on a device during this audit. Green CI proves compile/pure regression tests, not live GMMP resource availability or interface grammar.

**Contract:** The companion app and its Logs/Help are English-only. Inside GMMP, show native terms from the *host player's* live `Resources` and current app-specific locale; preserve original native views, menus, actions, theme and state where possible. Use one central GoneSmart-only fallback file only for genuinely missing feature-owned concepts. The two required non-native concepts are the **Move** command and the **virtual Other Locations** group label (the latter is *not* a physical folder name). Do not translate a real user's folder or playlist name.

### 3. Outstanding questions and release-hardening gates

1. **Potential native playlist Move/save primitive — REVIEW:** map original `zo3` / `hp3.d` writer's complete live model initialization, new destination binding, relative URI handling and `x6.b`/scanner index lifecycle using the privately inspected *same* original GMMP 4.2.0 APK. Existing native editor save does normalize relative playlist paths, but that observation alone does not prove it can safely relocate a playlist without stale records. **Keep the currently tested durable native-delete/native-scan Move workflow until such a complete alternative is established**.
2. **Native folder context popup — REVIEW:** the wrapper already inflates GMMP's original translated Delete menu item and invokes original `py0.b`, but does not reuse a proven specific Files-tab folder-context-menu presenter. Replacing it requires identifying its real model and callback contract; current accepted UI is not evidence of that mapping.
3. **Native configured playlist root — REVIEW:** Current `PlaylistRootLocator.infer()` conservatively recognizes only `Environment.getExternalStorageDirectory()/gmmp/playlists`, verified against at least one original native playlist path. **This is not reading GMMP's actual configurable `playlist_saveLocation`.** The original native `vp3.F → va4.getValue()` preference delegate is known and already verified **inside original `sp3`/`fo3` create callbacks**, where a mismatch safely cancels creation. A general read-only pre-browser resolver for that delegate has **not** been proven/installed, so a non-default configured GMMP playlist directory may fail to enable GoneSmart's folder browser. Do not guess an arbitrary common ancestor or change GMMP's preference; implement a verified read-only preference resolver if broader custom-root support is required, then test a non-default root on-device.
4. **Exact locale grammar/accessibility — REVIEW:** native resource lookups and fallback mapping are source-verified, but all 74 new virtual-folder translations have not undergone independent native-speaker review; neither has every locale's multi-add aggregate plural phrasing, mixed RTL directionality or a live change of GMMP's own language override. Screen-reader narration of all injected controls is part of the locale/device smoke tests.
5. **Alternative GMMP skins/versions — REVIEW:** existing tests validate the maintainer's GMMP 4.2.0 device and current skin. Source cloning samples native typography, layout, item animator and palette, but cannot guarantee pixel-identical behavior for every alternative skin, custom animator or later obfuscated GMMP release.
6. **Status detail tradeoff:** detailed English explanations previously leaked into GMMP Toasts. Host-player generic localized errors and icons now avoid that leak; richer localized diagnosis would require a **verified relevant native GMMP sentence** or **explicit newly approved, linguistically reviewed GoneSmart translations for all supported host languages**. English engineering detail remains in companion logs when emitted and in Logcat.
7. **No release implied:** The maintainer accepted the folder feature on the tested device; this branch-level audit and its CI do not authorize a signed public release, merging to main, or claiming new testing for untried languages/screens.

## 2026-10-01 GMMP 4.2.1 compatibility break

A device update from GMMP 4.2.0 to 4.2.1 demonstrated why the tested-version boundary must stay explicit even for small upstream releases. GoneSmart itself loaded, connected to remote settings and installed the verified Auto-DJ refill hook, but the next 4.2.0-specific reflection lookup failed with `NoSuchMethodException: kr.F1 [int]`. Because that lookup previously sat inside the outer startup transaction, the exception prevented all later independent hook families from being registered and made Playlist/Smart-Playlist UI features, Flip and other options appear completely dead.

The startup path now isolates the verified refill and selection hooks. A missing Smart-DJ boundary reports a degraded Smart-DJ runtime state but does not suppress unrelated hook registration. The 4.2.1 replacement mappings are **not guessed**: when `kr.F1(int)` is absent, runtime Logcat emits a bounded signature-only inventory of `kr` methods taking one `int`, then fails closed for that selection hook.

A follow-up 4.2.1 device trace also showed the 4.2.0 TrackDao query boundary `kr.g2/1` and the old Auto-DJ database field/accessor path missing under their 4.2.0 names. The first RawQuery diagnostic found `Q(qp4): List`, but invoking it proved that it is only the abstract inherited contract (`ys3.Q`) and throws `AbstractMethodError` on the runtime `kr` instance. GoneSmart therefore no longer treats an abstract List-returning method as an implementation. It now resolves a RawQuery fallback only from **concrete** methods and, when necessary, pairs one abstract List contract with exactly one concrete method using the same RawQuery parameter type; the returned object is still runtime-validated as a `List`. Any abstract invocation failure is marked deterministic so startup prewarm stops immediately instead of retrying.

The same trace identified the database remap unambiguously: `qr.s` is declared as `gonemad.gmmp.data.database.GMDatabase` and contains `GMDatabase_Impl`, while the old `qr.t` now contains `ur`. GoneSmart now prefers the old field only when it is still database-like, otherwise accepts exactly one structurally unique GMDatabase/RoomDatabase field. A subsequent device run proved that the existing `GMDatabase.y()` ArtistDao accessor still succeeds once the correct database field is used and returns runtime ArtistDao class `fn`.

The next 4.2.1 trace then showed that the old Artist query boundary `fn.R1/1` is itself gone. The bounded inventory exposes multiple one-argument `qp4` candidates, including List-returning `J1`, `Q` and `Q1`, so GoneSmart must not choose one by name/signature alone. The next diagnostic includes generic return metadata and the query wrapper is derived only after a unique semantic candidate is established. The old hard-coded `tp4(String,Object[])` assumption is retired.

That same clean-start trace demonstrates the **breadth** of the 4.2.1 R8 remap rather than one isolated Smart-DJ break. The old `bo3.I3()` Playlist-picker lifecycle entry is missing; Playlist Link lost its 4.2.0 `ft4` constructor/evaluation, `ds4` editor constructor/chooser, `ds4$g` scope class and `os2.U(gt4)` label boundary; Smart folders lost the old `ws4` constructor/writer, `ss4.P1`, `os4.j2`, `ss4$b` and `nt4.c`; Flip/Track Auto-DJ lost the old `ex3.D`, `ex3.b2(int)`, apparent `ex3.w(List)` observer and `MusicService.w1(int,Object,List)` entry. In contrast, Auto-DJ refill, player badge, startup-prewarm registration, native `n3` Smart ActionMode and the menu inflater paths still install. This cross-version matrix is maintained in `docs/GMMP_COMPATIBILITY_PLAYBOOK.md`; this audit keeps the dated evidence.

The latest TrackDao structure is `kr > gr > ys3` with `u → GMDatabase_Impl`, `v → kr$a` and `w → kr$c`. The abstract `ys3.Q(qp4): List` remains a contract only. GoneSmart now inventories the concrete delegate fields rather than guessing another top-level method. The Auto-DJ selection resolver is hardened separately: the verified `F1(int)` name remains the 4.2.0 fast path, while a later build may use a fallback only when there is exactly one concrete `int → List` candidate.

The same run confirms that startup prewarm now stops immediately after the unresolved TrackDao mapping. Large UI frame drops still occur after that stop while GMMP creates/refreshes many of its own library fragments, so those remaining startup stalls must not be attributed to the old GoneSmart retry loop without separate evidence. The companion Home Compatibility warning now uses an amber/orange **full-width bottom section** with normal status text for any installed GMMP version other than the explicitly tested version; it is not an inset warning card inside the green module state.

The next compatibility hardening pass also removed two avoidable failure cascades before any further remapping: the Add-to-Playlist picker now attempts its `I3` / `k2` / `D1` observers and native handler independently, and its failure no longer blocks the separately verified native playlist-creation hook family. Likewise, the missing 4.2.1 `ws4.t(File)` Smart writer is caught locally so ordinary Playlist surface hooks are still attempted. These changes do **not** declare the remapped functions compatible; they only preserve unrelated native paths and make the next clean-start diagnostic complete.

## 2026-09-30 release-prep audit consolidation

The completed Playlist/Smart-Playlist feature set was re-audited against the current branch after the final Smart-folder and creation-dialog device passes.

- **Playlist Link:** the end-to-end, disabled-module and independent live-switch paths are accepted on the maintainer's GMMP 4.2.0 setup as of 30 September 2026. The obsolete debug-PoC gate has been removed. Only the functional Smart-editor/link/evaluation hooks are installed in release builds; generic reader/query/save reverse-engineering probes were removed. The companion switch defaults ON. When switched off, internal Bridge-specific UI/evaluation interception falls through to GMMP's original V2 compatibility rule instead of deleting or rewriting saved Link leaves.
- **Playlist folders:** accepted runtime hooks remain release-enabled. The old native-save trace and move-discovery probes were removed because the current staged native-delete/native-rescan move contract is already established. The known custom-root limitation remains documented rather than guessed around.
- **Smart-Playlist folders:** real `ls4/vs4/ws4` rows remain native; the shared folder UI kit/move chrome remain the required presentation path. The current extension-owned multi-selection, guarded Smart Move and native stretch/MotionEvent scroll contract are the accepted runtime behavior.
- **Companion UI:** the two playlist sections now intentionally expose the same primary labels (**Multi-selection**, **Folders**) and surface-specific explanatory text. This is companion-only English copy and does not affect GMMP locale handling.
- **Logs:** folder/grouping/multi-selection and Playlist Link option changes now emit concise `[UI]` events. The companion summary separates `UI` and `System` instead of folding both into Other. Playlist Link publishes only high-level System readiness to the companion; detailed Bridge data stays in privacy-safe Logcat.
- **Exploratory logging:** temporary playlist-surface discovery, Smart-loader discovery and native playlist-save/read/query probes are not shipping requirements and were removed. Bounded diagnostics that still protect a live compatibility boundary may remain, but must not become a permanent second behavior path.
- **No broader validation implied:** this cleanup does not add a new GMMP version, skin, locale or signed-release device test. The maintainer's accepted GMMP 4.2.0 results remain the evidence base.
